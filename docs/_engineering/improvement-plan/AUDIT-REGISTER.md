# Audit and design register

This register connects every active audit and design input to the maintained
program and to the checkpoint that must disposition it. It is an index and work
map, not a second specification: [README.md](./README.md) owns decisions and
program rules, the `IP-` phase files own requirements and evidence, and
[IMPLEMENTATION-RUNBOOK.md](./IMPLEMENTATION-RUNBOOK.md) owns execution order.
Point-in-time reports retain their detailed evidence, alternatives, test ideas,
and rollback notes until their retirement gate is met.

If a report conflicts with a later recorded decision, the decision wins. If a
document conflicts with code, code is the current behavior until the owning
checkpoint reconciles both. No row here can verify an
[ACTION-REQUIRED.md](./ACTION-REQUIRED.md) item.

## Retirement and documentation rule

A source report may be removed only when every finding it owns is implemented,
explicitly deferred, or superseded with linked evidence, and no unique test,
rollback, manual-check, or platform guidance would be lost. Before removal,
extract shipped behavior into maintained architecture documentation. The target
documents are `docs/_engineering/tracking/tracking-runtime.md` and
`docs/_engineering/sync/sync-architecture.md`; neither should be created from a
proposal before the corresponding behavior exists.
